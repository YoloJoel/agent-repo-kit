# Content and final-state checks

## Configuration
Generate supported spec-driven YAML using literal context and JSON-quoted rule scalars. Initial
observations remain unreviewed; curate entry facts before refresh. Never overwrite native/edited
config; the Agent reconciles it in place and records an actual review. Bind config, facts, authority,
AGENTS and source evidence. Guards intentionally do not parse arbitrary YAML/custom schema semantics.
Native instructions consumption is independently exercised in the pinned OpenSpec qualification.

## Registry and navigation
Discover candidates from the actual contract tree, native kind metadata, known contract sections
and current-spec contract references. Do not derive all audit scope from a potentially incomplete
registry. Registered history remains immutable in raw snapshots. Derive a bounded navigation block
from real declaration/currentness state, preserve native bytes outside it, refresh after transitions,
and expose stale views or referenced unregistered contracts as non-PASS.

## Final state and test boundaries
Persist final declaration input hashes only after live structure/content/audit checks. Snapshot the
inputs before/after the check and detect changes. Later source/config/test/registry/audit edits
invalidate that record. Dates alone do not establish staleness. Missing test mappings already block
verified claims as PENDING; expose counts by spec rather than silently accepting test-less stacks.
No mapping, source review or final declaration asserts that business tests were executed.

## Verification
Counterexamples cover empty/generic/duplicate config and native preservation, orphan contracts,
current audit artifact scope, navigation state/native CRLF preservation, final-input staleness/race,
new-repository applicability and empty-structure/test-mapping boundaries. Real fresh and 0.2.5
upgrade model tasks exercise the shipped workflows on public journal source. Actual unit checks,
semantic findings and final partial states are retained; no global semantic-equivalence claim.
