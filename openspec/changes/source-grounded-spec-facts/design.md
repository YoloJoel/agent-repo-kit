## Design

Reuse existing Baseline/contract sections and behavior-inventory fields for factual rows.
The new source-facts reference defines concrete reads and falsification attempts for fragile
claim types. Link it from both onboarding entry points and both source audit passes.
Keep registration/literal facts separate from definitions and actual assertions separate from
requirement-ID declarations. Complete each behavior batch before continuing the next one.

The runtime continues to check declaration consistency and input currency. This revision
changes the authoring/review procedure and its evaluation assets. It does not infer arbitrary
business semantics from source text. Existing accepted conflicts keep their decision history.

Use an isolated C fixture with original passing but incomplete tests. Verify native behavior
and a deliberately changed rule independently. Forward tasks receive source, original tests,
installed Skill and a normal user request. Keep evaluator ground truth outside those inputs.

## Verification

Run source/installed-package tests, generated resource checks and the actual native probes.
Independently inspect model-produced clauses and uncertainty dispositions. Report demonstrated
workflow behavior, model/task limits and private-project follow-up distinctly.
