# Local delivery integrity

## Approach and boundaries

Replace the finite behavior suffix decision with a conservative unknown-input fallback.
Keep recognized documentation light; behavior_paths marks runtime-consumed documents.
The effective-spec matrix runs independently of a selected Change and cannot be waived by
format-debt exceptions. Explicit required delivery-check mappings support native titles and
other test systems; reference text still cannot establish assertion quality.

## State and failure

Registered knowledge is scoped by source or document impact. Stale current declarations
produce PENDING, while unrelated records and explicitly retired history do not block.
Re-review writes a new immutable snapshot without replacing pre-change executed anchors.
Startup remains navigation-only; checks execute at the existing local verification boundary.

## Compatibility and migration

Use explicit initialize-repo --upgrade for 0.2.0 consumers. Preserve existing paths, IDs,
human content, historical raw, accepted decisions and native lifecycle. Former false PASS
results now fail or remain pending. Optional Git/CI integration uses the same local entry.

## Verification

Exercise the original failures and legitimate recovery, required check phases, external
type preservation, runtime documents, unrelated stale knowledge and historical retirement.
Run source and installed-wheel suites plus artifact consistency. Independently initialize
an empty project, onboard source-only cachetools and continue development in a fresh session;
evaluate actual content, tests and negative mutations. Native host loading/trust remains a
separate claim from these model-driven workspaces.
