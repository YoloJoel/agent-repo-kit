# IT-09：复测前统一收口

用户的完整实仓复测成本高。本轮先完成可在工具仓内复现和验证的工作，再固定一次交付。

| 范围 | 工作和验收依据 |
| --- | --- |
| 运行内核 | 修复轻量检查运行期输入失效、完整复合 REQ 依赖、原生 close 交接、相对执行器就绪诊断和字面量伪断言 |
| 内容质量 | 使用固定参考源码的 61 文件派生输入和 237 文件原始治理输入，独立执行完整接入；另从源码建立独立审查参照 |
| 原有资产 | 核对业务源码/测试/配置、人工规则、规范编号、原始历史及活动变更的实际变更，保留未核实范围 |
| 演进与恢复 | 实际旧版升级、幂等、接续及原生两轮 OpenSpec 生命周期 |
| 分发与验证 | 源码、安装 wheel、自包含 vendored 路径、两个 Skills、原生多语言探针和跨平台 CI |
| 记录收口 | 以已合入 PR 和实际成功 CI 对账历史未勾选发布项，保存本轮输入、输出及限制 |
| 最终交付 | 完成全部已确认问题和检查后固定一个提交供用户复测；私有参考内容不发布到工具仓 |

参考仓本身是私有仓。完整原始审阅与接入产物作为私有记录保存，对外仅给出脱敏结论和指纹。
参考输入中的缺失业务实现、外部系统和未验证的宿主信任不由模板或声明补成 PASS。
没有新增用户操作步骤、第二套任务权威源或必经日常 Skill。
