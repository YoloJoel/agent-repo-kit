## 实施原则

- 程序检查负责可确定的事实；模型负责语义理解，独立审阅和真实执行提供不同证据。
- 不用关键词黑名单或固定业务值修补单个样例；不把多填 JSON 当成理解能力完成。
- 保留原始记录和已接受承诺。新证据要求不把旧历史批量升级成当前通过；给出迁移缺口。
- 新接口以 Python 标准库实现，保持离线、自包含分发；按职责组织可测函数，避免无关拆分。
- 每轮记录实际命令与反例。适用完整测试在集成点执行，随后检验 wheel 和 vendored 入口。

## 外部验收输入

模块 M 的冻结源码、人工/Kit Spec、真实依赖及原评测环境未随任务提供。
真实宿主模型会话的能力取决于本执行环境。工具侧实现、公开正反例和本地交付可继续；
外部任务必须具备输入后才能报告成绩，不用合成夹具替代。最终报告逐项列实现和实测状态。
