# IT-08：行为取证与持续质量

用户反馈：目录/文件齐全并不代表行为完整；源码行号、测试 ID 和审计声明也不能证明语义正确。
本轮以 0.2.6 为起点，保留现有路径、规格、ID、人工规则和历史。默认仍只有两个接入 Skill。

| 工作包 | 本轮实现与验收 | 不能由此宣称 |
| --- | --- | --- |
| 1 行为建模 | 独立行为清单，跨目录调用/契约，横切面适用性；行为分母和缺口 | 自动发现所有业务行为 |
| 2 取证 | 入口/分支/调用/使用点/副作用锚点、生效条件；源码与产物快照 | 行号和声明本身证明语义 |
| 3 不确定性 | verified/inferred/unknown/defect 与 current/baseline/gap 分离 | 所有实际代码行为都是应保留承诺 |
| 4 语义审计 | 逐条反证、替代解释、跨规格同条件契约冲突；最终源码复核 | 文本解析器能理解任意业务语言 |
| 5 测试可信度 | 每条断言的输入/期望/断言锚点/真实检查；降级理由和未执行状态 | 注释引用、编译、测试数等于覆盖 |
| 6 持续维护 | 行为依赖的传递影响、源码/规格/测试变化使声明过期 | 静态路径关系是完整调用图 |
| 7 工程执行 | 原生命令优先；C/C++、Java/Python 的可复现正反验证，环境阻塞单列 | 自动修好业务仓或支持所有工具链 |
| 8 评测与接入 | 反例基准、实际模型任务、新仓/升级、发行安装一致性；统一仓内入口 | 小型夹具替代大型真实项目验收、所有宿主 Hook 生效 |

执行顺序：先建立评测反例与协议，再实现记录/检查/影响，修改 Skill 生成和审计流程，
完成原生构建回归、独立任务验证、安装包与跨平台 CI，最后发布。本轮工作记录和证据另附。

已有大仓反馈是问题输入，未获得其源码；不会编造该仓的语义覆盖、测试执行或修复结果。
私有大仓和多种运行器的长期使用质量继续按实际证据验收。本轮提供可执行基础及明确剩余范围。
