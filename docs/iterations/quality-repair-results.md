## 原始五个反例

| 反例 | 修复后的观察 | 对应 test_quality_repairs.py 回归 |
| --- | --- | --- |
| R1：只登记失败 case | 已登记样本自身仍可显示 1/1；独立 return-true 候选使最终 onboarding PENDING | test_one_declared_failure_case_cannot_complete_source_discovery |
| R2：含糊结果与正确猜测 | 旧决定前提不能复用；模糊预测不能因源码值相同裁为 entailed | test_undefined_result_cannot_reuse_old_deciding_premises；FrozenReadbackTests |
| R3：无 SHALL 的错误 Scenario | 完整块未绑定或发生变化即待审，包括 WHEN/THEN/表格/fenced 输出 | test_added_wrong_scenario_is_not_silently_outside_review；fenced/条件回归 |
| R4：调用片段冒充断言 | 完整 Python AST 语句核对拒绝普通子表达式 | test_call_substring_is_not_an_assertion |
| R5：定义但不调用测试 | command_status PASS，case_execution 未执行，ready/delivery PENDING，不建立锚点 | test_never_called_regression_cannot_anchor_or_deliver |

R2 仍依赖裁定者正确判断文本充分性；程序不能阻止错误的语义裁定。冻结文件/身份也不能证明上下文隔离。
修复的是可确定的漏洞和可审查过程，最终质量必须由独立读者实测。
