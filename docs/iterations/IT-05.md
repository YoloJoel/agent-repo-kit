# IT-05 — Executed original behavior and target verification

Established behavior now requires a scoped verification matrix and actually executed old
checks before implementation. The matrix can live with native work assets or use an existing
mapped path; it is not an alternative development workflow. Original sources, fixtures,
command definitions, environment, actual logs and results are bound into immutable baseline
snapshots. Delivery runs regression and intended target checks and reports each case's before
and current status. Planned cases remain distinct from executed checks.

A once-empty project acquires the same obligations once code is committed or successfully
delivered, including a local directory without Git/remote/CI. A later ready invocation cannot
replace original evidence. Changing a regression fixture/plan/command invalidates reuse.
Intentional replacements identify old expectations, old-only checks and a real decision;
target expectations are verified separately. Missing external conditions remain pending.

Native project argv are reused. Optional replay compares recorded JSON without modifying
inputs; normalization requires specific existing output leaves and an explicit reason. Raw
hashes and normalization remain visible; a business difference still fails.

Validation: 84 source workflow tests pass, including original execution, equivalent refactor,
negative/error behavior mutation while normal target passes, unavailable old environment,
handwritten anchors, altered regression fixtures, phase-excluded target checks, JSON replay
and no-Git new-project evolution. The three older positive fixtures now execute their old
behavior instead of treating static review as runtime evidence. Installed-wheel and all
platform/installer results are linked from this iteration's PR. Java/Maven real-repository
qualification is recorded in the final acceptance iteration; command protocol alone does not
establish support for every language/build ecosystem.

These records are auditable repository evidence, not a security boundary against an actor
rewriting the checker, policy and history together. Reviewers still assess case completeness,
meaningful assertions, accepted compatibility choices and external evidence authority.
