# IT-04 — Executable engineering validation

## Result

Native requirement titles and existing IDs remain intact. A title without an explicit ID is addressed as capability::title for local check mappings. The bounded Markdown reader ignores fenced examples, checks normative behavior and WHEN/THEN scenarios, validates verification types and source links, and understands native FROM/TO renames. It is a structural checker; OpenSpec remains responsible for native schema validation, synchronization and archive.

Current/retired identities, ADR numbers/lifecycle/supersession, promoted knowledge references, risky-refactor design and actual diff scope are checked. Raw evidence, Accepted ADR bodies and already archived files are protected against the real comparison base. Missing comparison history cannot establish immutability; this is not a security boundary against changes to the checker itself.

Specification review does not execute business commands or authorize completion. Delivery runs required checks and close requires fresh local delivery evidence. Human verification prose is preserved outside one managed region; malformed markers fail without overwriting the report. Explicit automated check mappings can supply navigation without inserting artificial ID comments into tests.

Format-debt exceptions are limited to wording/scenario/verification-format findings, bound to exact source and decision hashes, reason, owner and expiry. Missing checks, failing commands, history corruption and retired identities cannot be waived. No exception is generated automatically.

## Validation

The interrupted workspace had passed 75 tests for the initial implementation. Recovery reconstructed the source through GitHub; the authoritative acceptance for this PR is the complete installed-distribution, native-artifact and installer CI at its final head, including the new specification regression suite. Do not interpret the interrupted local result as validation of the recovered final content.

Added negative cases cover missing outcomes, broken links, invalid supersession, retired IDs, exact ID boundaries, unfinished delivery, malformed report markers and expired/changed exceptions. Positive cases cover native titles, foreign IDs, fenced examples, scoped check mapping and stable-ID rename. CI is for validating this toolkit distribution; consumer repositories still require neither GitHub nor CI.
