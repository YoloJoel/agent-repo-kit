# 0.2.5 全仓接入与自动规格初始化

## 原因和修复

旧流程要求分模块和保存检查点，却未明确默认全仓、自动选顺序并继续下一批；
使用指南还要求原生工具单独初始化。Agent 因此可能把常规编排误作用户决策。

- initialize-repo / baseline-repo 裸调用默认全仓；纵切只是批次，由 Agent 自行排序。
  保存完整能力图和接续状态，自动继续未完成批次；实际阻塞保持 PENDING，推进独立范围。
- 首次写入前检查规范权威：沿用已有 policy/原生规范及 IDs，没有时使用 OpenSpec 布局。
  doc/specs 只有目标设计时不能据此认定为现行规格；已有权威规范时不另建竞争目录。
- 本机已有兼容 CLI 时按实际帮助自动安全、非交互初始化缺失配置；保留人工资产和映射。
  CLI 缺失/不兼容/无法安全初始化时记录原生步骤 NOT_RUN，继续源码 Baseline 和实际 Spec。
  不自动下载包探测 CLI；目录存在、工具脚手架和原生初始化是不同结果。
- 实测复现并修复：生成入口追加托管区外备注后，刷新不再丢失七段项目内容；仍保留原生入口和人工文本。
- 不再要求选择首个纵切、逐批确认继续，或常规选择 doc/specs/OpenSpec。
  仅无法从可读规则解决的权威冲突、实际业务取舍等才需要用户决定。

裸调用实测及实际生成产物、输入保留和限制见 ../evidence/onboarding-defaults-use.json。

这些流程约束及样例不保证任何模型、任何大型私有仓都不会遗漏语义。
