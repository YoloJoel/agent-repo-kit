# 0.2.6 配置内容、孤悬契约与终态验收

## 修复

- OpenSpec 适用时，初始化产生实际 schema/context/rules；从源码事实补全后由实际 Agent 检查再登记。
  保留原生 schema、人工规则/注释和已编辑配置；非 OpenSpec 权威不会被强制迁移。
  空配置、只有框架/语言、缺规则、重复顶层字段和过期内容保持非通过。结构守卫不是完整 YAML 解析器，
  原生读取/校验与配置内容复核分别报告；可用 CLI 的真实消费另由原生资格检查验证。
- 从磁盘契约目录、原生 kind、已知契约段落和当前 Spec 引用反查登记遗漏；被引用但未登记的契约不能
  被已登记范围掩盖，也仍属于最终源码审计必须覆盖的产物。
- 登记、晋升、退役后派生 Baseline 导航，保留人工正文/front matter/换行；源变化导致过期时提示刷新。
- 最后运行 onboarding-status --record，实时重查结构和声明并绑定最终源码、配置、测试、登记及审计输入。
  之后实际输入变化会过期；仅时间戳变化不算过期。空规格的 structure PASS 明确只代表相应结构范围。
- 缺自动化映射继续阻止已验证完成的声明，新增按规格计数。没有测试目录不是豁免，也不通过更改
  Verification 类型、虚构测试或把编译称为业务验证来变绿。
- CHANGELOG 补齐 0.2.5/0.2.6；兼容性与旧验证记录明确区分当前版本和历史日期，保留当时真实结果。

## 验证与限制

最终源码和实际安装包各 156 项测试通过，新增反例覆盖项目配置、原生保留、孤悬契约、导航和终态时效。
实际 fresh 与 0.2.5 升级任务读取公开 journal 源码并执行原测试，保留已有源码/测试、权威路径、编号和
历史；两轮源码复核各发现并修正文档遗漏。整体仍 PARTIAL/PENDING，缺失事实/测试和运行环境未假报通过。
升级样例的新独立审计通过，但旧登记审计因升级变动而过期，聚合审计保持 PENDING，历史未被删除。
这项既有聚合行为如需改变，应增加明确的历史/取代语义，不能靠删除过期记录掩盖。

真实工件摘要、最终内核查询、输入哈希和限制见 docs/evidence/onboarding-completeness-use.json。
最终 CI 与合入结果见本版本 PR；此本地报告不是对私有业务仓的验收结论。

## 用户已有仓接续

更新 Plugin/Skills 后调用 initialize-repo 升级并接续；保留现有 Spec/人工规则/编号/历史。
正常流程会补配置、核查并登记遗漏契约、更新索引、重新源码复核，然后记录最终状态，无需清空。
实际业务测试仍需在本地补齐或运行；工具仓通过不代表业务仓的自动化承诺已经得到验证。
