# 0.3.1 源码事实与断言复核

实仓反馈显示，0.3.0 的行为清单、源码锚点、反证和审计记录仍可能伴随错误的业务承诺。
有定义的资源未必注册，有范围检查函数未必被调用，有容量常量未必等于生效边界，
时序和生命周期也可能被其他路径改变。泛化成功断言可以让多条未被观察的条款看起来有覆盖。

## 本轮改变

接入入口继续使用 initialize-repo。baseline-repo 在每个行为批次先从源码记录事实，
再写条款、核对实际断言并重读源码。事实记录复用已有 Baseline/契约和行为清单，
保留现有 ID、人工规则和决定，继续使用已有证据协议。

| 声明类型 | 本轮要求的具体核验 |
| --- | --- |
| 注册、命令、标识和协议字面量 | 从生效表和构造路径逐项摘录，核对条件、数量及未知输入 |
| 范围、容量和安全拒绝 | 追到解析、校验调用、分配、下标和错误结果，检查边界两侧 |
| 完整性、确认、持久化和清理 | 核对生产端写入、消费端实际检查/提交及失败结果 |
| 窗口、超时和过期 | 明确唤醒来源、时钟单位、比较条件、重置顺序及没有新事件时的行为 |
| 策略顺序和条件更新 | 从有序分支建立条件表，包含两条件同时满足的情况 |
| 进程、信号和共享状态 | 读取启动装配、最终回调/信号注册以及实际读写方 |
| 自动化关联 | 每条条款和场景核对测试输入、到达的分支、实际观察和断言 |
| 条款与证据范围 | 对齐承诺的完整输入域；默认值或单个子域的证据不能关闭无条件条款 |

缺陷和未知项按事实保留处置。当前规格与已接受决定冲突时继续登记差异。
范围排除要记录理由及仍属于本仓的交互边界。业务测试缺口和真实执行结果分别报告。

## 可复现验证

`examples/control-hub` 是有原始 C 源码和五条既有测试的隔离样例。
运行 `python tools/qualify_source_facts.py --output <证据目录>` 可重现这些实际结果。

| 路径 | 实际观察 |
| --- | --- |
| 资源和命令 | 注册两个资源，未登记的命令返回 -1 |
| 消息字段 | 输出 token 为零，接收端读取载荷而未比较该字段 |
| 配置范围 | 校验函数拒绝 700，实际更新入口接受 700 |
| 容量 | 分配常量为 6，实际配置入口接受 4、拒绝 5 |
| 策略 | 全局和局部规则同时启用时选择全局 |
| 窗口 | tick 不产出，边界时刻不产出，下一事件触发且可产出空字段报告 |
| 终止 | 最后安装的 SIGTERM 处理器生效，进程以信号退出，未观察到刷新输出 |
| 断言缺口 | 临时改变规则输出，原五条测试仍通过；恢复后原测试继续通过 |

探针的 PASS 表示上述有界观察与预期相符。原五条测试的通过只覆盖其实际观察，
不表示样例的所有行为已经有断言。脚本在临时副本执行并保存真实输出、退出码和日志哈希。

本地源码和已安装 wheel 各 189 项测试通过；生成的两个 Skills 及资源一致性通过。
0.3.0 安装副本升级后保留人工入口，重复升级没有变更；最终 CI 以 PR 的实际运行结果为准。

## 模型样例的实际结论

对同一份小型 C 源码和原始测试，分别用 0.3.0 与本轮候选资源执行过隔离接入，
并独立审查实际产物。两版都识别出大部分决定性源码事实，也都如实保留了测试缺口。
新版候选产物仍出现一处范围不一致：条款无条件描述接收结果，行为证据只提升了
token 为零的子域。最终资源因此补充条款与证据完整输入域的逐项对齐要求。
这组结果没有证明新版显著优于旧版，也没有证明真实大仓的缺陷已消除。

上述两次接入的临时原始产物随后过期，仅保留会话总结，不能作为可独立复算的比较数据。
本轮重新执行了一项独立的只读审计回归，保留输入规范、映射、任务、源码指纹和原始报告。
该回归识别了两个预置源码矛盾、无关成功断言和完整输入域未对齐问题；它验证审阅步骤
在这个合成样例中的表现，不代替从零接入复测，也不充当丢失产物的恢复件。
可复查记录见 [本轮证据](../evidence/source-facts-use.json)。

## 验收范围

本轮修订生成和审阅的执行步骤。运行内核继续检查声明关系、状态和时效，
业务语义由源码分析和实际执行建立依据。用户私有仓的上述错误尚需用新版实际重跑。
用户的 DeepSeek 运行器、完整外部依赖和生产行为仍待原环境验证。
