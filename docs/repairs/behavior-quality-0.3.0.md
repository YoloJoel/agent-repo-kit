# 0.3.0：从文件声明到行为取证

本轮按 [八个工作包](../iterations/IT-08.md) 执行。0.2.6 已有源码审计和哈希绑定，
不足是生成/复核粒度仍偏文件和能力，不能证明逐条行为、分支和断言。没有把已有机制说成不存在。

| 反馈 | 本轮改变 |
| --- | --- |
| 按目录生成导致横切遗漏 | 生成前独立发现触发、调用、状态、副作用和跨模块契约；显式检查八个横切面适用性 |
| 常量/同名符号代替生效证据 | 区分定义、入口、调用、配置使用、分支和效果，必须解释生效条件 |
| 正向泛化成可靠保证 | 七个维度逐项审查，逐条尝试反例/替代解释，best-effort 不升级可靠送达 |
| 推断升级规范 | verified/inferred/unknown/defect 与 current/baseline/gap 分离，未核实当前承诺不能通过 |
| strict 格式代替语义 | 所有规范句关联行为审查，反证和同条件 canonical 契约冲突阻止完成；真实语义仍由源码审阅 |
| 测试引用只是注释 | 输入/期望/实际断言片段/检测错误原因/命令映射，保留验证降级和缺口 |
| 文件数替代覆盖 | 行为清单分母、已复核/未知/缺口分列；比例仅针对已发现清单 |
| 形式修补和漂移 | 源码/测试/规格/policy 哈希及原始快照、传递影响、新源发现、统一 delivery/close 门禁 |

增加工程 readiness、日志哈希/进程信号和原生工具链复现要求；真实 C/C++/Python 探针
执行原实现通过、故意改坏失败、恢复通过。本地只有 JRE 无 javac，Java NOT_RUN，
CI 单独提供 JDK 执行，不把配置当结果。探针不证明大规模工程、Redis/DB/设备兼容性。

活动 Change 可通过真实两遍源码/目标/断言审计支持候选交付，不提前改写 current spec。
全部 proposal/design/tasks/delta、关联测试、当前规格和 inventory 必须实际审计；审计后
变化不能只重拍 fingerprint。current/target 验证方式可分别映射到实际 Change。原生工具
负责同步/归档；候选审批不表示 current baseline 已刷新，不引入第二套生命周期。
